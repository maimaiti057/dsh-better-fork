# Better Fork

> Branch from a compaction card, edit its summary, and start the new session from the node that actually matters.

Better Fork is a DSH session enhancement plugin. It adds two direct capabilities around **compaction cards**: **compaction card branch** and **compaction card edit** — open a new branch from the card, or edit the compacted conversation summary. It builds on the official fork, official `/compact`, and official compaction cards.

---

## Core capabilities

### Compaction card branch (Branch button)

A card generated by a manual `/compact` gets a **Branch** button. It creates a normal official fork at the card position without rewriting the summary — useful when you want to continue from an already-organized compaction node instead of the end of the session.

### Compaction card edit (Edit compacted summary)

What you edit here is the **compacted conversation summary**, not the original context.

When the latest card comes from a manual `/compact` and a new conversation has not started yet, you can open the editor and change the official summary. The original conversation stays untouched, so cache hit rate remains more stable.

### Compaction summary translation

Translates the compaction summary into Simplified Chinese. Other languages can be added by extending the plugin. Only the draft changes; submit to apply.

### Remove conversation tail

If you do not need the conversation tail kept after compaction either, remove it explicitly in the editor and leave only the summary. One-way operation, no restore; unavailable while the session is running.

---

## New feature

### Start here

**Start again from any reply.** In a long session, the most valuable point is often not the last message, but the node where a problem was just clarified or an approach just validated. Official forks usually start from the end; to keep an earlier node, you either chat another round or carry later detours with you.

"Start here" uses any assistant message as the boundary: fork first to keep the prior context, then run the official `/compact` to turn that context into an editable summary. Forking alone carries the whole history; compacting alone only handles the end. Together they give you a clean starting point without losing the prior context.

---

## Usage

1. Develop normally and build up a long session.
2. When you want to continue from a node, click **Start here**; or click **Branch** directly on a manual compaction card.
3. To adjust the summary, click **Edit** on the card and modify, translate, or remove the tail.
4. Continue in the new session; when a starting point works well, use official fork again to copy it.

### Compaction card actions

| Action | Condition | Behavior |
| --- | --- | --- |
| Branch | Manual compaction card | Normal official fork; no compaction, no summary rewrite |
| Edit | Latest manual compaction card, before a new conversation starts | Edit the compaction summary; translate or remove the tail |

---

## Design philosophy

**Edit the summary, not the original conversation.** Editing the original conversation would change the official context structure and lower cache hit rate; the compaction summary is what the model reads, so editing it lets you change direction while preserving the original conversation and cache.

**The compaction card is a natural boundary.** It closes the previous context and starts the new session; branching and editing belong there, without inventing another summary or branching mechanism.

**Official first.** No new context format, no replaced official buttons, no bypassing the official session flow; after compaction, fork, or edit, global/project `AGENTS.md` is still injected through the official mechanism.

**The session is everything.** The session itself is the project asset; forking does not copy files, it copies a context that already understands the project. Instead of writing project summaries, manage the session, trim the summary, and fork clean starting points — a project-specific agent grows naturally.

## Installation

Install and enable `dsh-better-fork` in the current DSH profile, then refresh the Web UI. The plugin list shows "更好的分叉" or "Better Fork" based on the interface language.

---

## Compatibility

Validated baseline: DSH `0.2.1-rc.2` · plugin `0.1.0` · Windows desktop.

Other DSH versions are not individually validated. See the upgrade checklist and known fragile points in [DEVELOPMENT.md](DEVELOPMENT.md), and adapt as needed.
