# 更好的分叉 · Better Fork

> 压缩卡上的分叉与摘要编辑，让新会话从真正有用的节点开始。

Better Fork 是 DSH 会话增强插件。它围绕**压缩卡**提供两个直接可用的能力：**压缩卡分叉**与**压缩卡编辑**——在卡片上开新分支，或修改压缩后的对话摘要。底层沿用官方 fork、官方 `/compact` 与官方压缩卡。

---

## 核心能力

### 压缩卡分叉（分支按钮）

由手动 `/compact` 生成的压缩卡上会出现「分叉」按钮，从卡片位置直接开一个普通官方分支，不改写摘要。适合从已经整理好的压缩节点继续，而不是回到会话末尾重新开始。

### 压缩卡编辑（修改压缩摘要）

这里编辑的是**压缩后的对话摘要**，不是原始上下文。

最新一张手动压缩卡、且尚未开始新对话时，可以打开编辑器，直接修改官方生成的摘要。原始对话保持不动，缓存命中率也更稳。

### 压缩摘要翻译

把压缩摘要翻译成简体中文；需要其他语言，可自行添加。只改草稿，确认后再提交。

### 移除对话尾部

如果连压缩后保留的对话尾部也不需要，可以在编辑器里显式移除，只留下摘要。单向操作，无恢复；会话运行中不可用。

---

## 全新功能

### 从这里开始

**从任意一条回复重新开始。** 长会话里最值得保留的，往往不是最后一条消息，而是某个问题刚讲清楚、方案刚验证的节点。官方分叉通常从末尾开始，想保留更早的节点，要么再聊一轮，要么把后来的试错一起带走。

「从这里开始」以任意 assistant 消息为边界：先 fork，保住前文；再走官方 `/compact`，把前文收成可编辑的摘要。只 fork 会带走整段历史，只 compact 又只能处理末尾；两步合起来，才有干净起点，也不丢前文。

---

## 使用指南

1. 正常开发，积累长会话。
2. 需要从某个节点继续时，点「从这里开始」；也可以在手动压缩卡上直接「分叉」。
3. 需要调整摘要时，在压缩卡上「编辑」，修改、翻译或移除尾部。
4. 提交后继续开发；效果好的会话继续用官方分叉复制起点。

### 压缩卡操作

| 操作 | 条件 | 行为 |
| --- | --- | --- |
| 分叉 | 手动压缩卡 | 普通官方 fork，不压缩、不改摘要 |
| 编辑 | 最新手动压缩卡，且未开始新对话 | 修改压缩摘要；可翻译、移除尾部 |

---

## 设计理念

**只改摘要，不改原始对话。** 直接编辑原始对话会改变官方上下文结构，也会拉低缓存命中率；压缩摘要本来就是模型读取的内容，改它才能在调整方向的同时保住原始对话和缓存。

**压缩卡是天然的边界。** 它既是上一段上下文的收口，也是新会话的起点；分叉和编辑都放在这里，不必再发明一套摘要或分支机制。

**官方优先。** 不新增上下文格式，不替换官方按钮，不绕过官方会话流程；压缩、fork、编辑后，全局 / 项目 `AGENTS.md` 仍按官方机制正常注入。

**会话即一切。** 会话本身就是项目资产；分叉不是复制文件，而是复制一个已经理解项目的上下文。与其写项目总结，不如管理会话、修剪摘要、fork 出干净起点，让项目专属智能体自然长出来。

## 安装

在 DSH 当前 profile 中安装并启用 `dsh-better-fork`，刷新 Web UI。插件列表名称随界面语言显示为「更好的分叉」或 Better Fork。

---

## 兼容性

当前验证基线：DSH `0.2.1-rc.2` · 插件 `0.1.0` · Windows 桌面版。

其他 DSH 版本未逐一验证；可直接参考 [DEVELOPMENT.md](DEVELOPMENT.md) 的「升级检查顺序」和「已知脆弱点」，自行完成适配。
